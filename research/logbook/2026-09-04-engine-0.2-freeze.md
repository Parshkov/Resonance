## What was found

1. **Corpus pollution had a cause, not just a symptom.** `abc_mcp_test.py` revoked only identity A;
   `hosted_onboarding_probe.py --smoke` shared a thought and never revoked it. Both now revoke their
   own guests (and assert that nothing of theirs stays discoverable), including from `finally` on a
   failed run. Measured effect of the existing pollution: in the `9a79eb8` A/B/C run the genuine
   cross-domain analogy sat at **rank 4**, behind three exact copies of the query's own thought all
   scoring structural 1.0.

2. **The recorded diagnosis of the A/A' verdict was wrong.** The previous evidence said one
   contradicting relation demoted an otherwise systematic mapping from `analogical` to
   `approximate`. `classify()` reaches `analogical` only when surface similarity **and** domain
   overlap are both below threshold; this pair shares vocabulary (surface 0.44 ≥ 0.30), so it takes
   the same-subject-matter branch where `analogical` is unreachable by construction. Whether that
   branch should be gated on domain overlap alone is a genuine policy question with **no gold case
   behind it** — Benchmark v0.2's cross-domain family substitutes vocabulary as well as domain.
   Recorded as **ADR-0005, status open**, with an explicit refusal to settle it by moving
   `T_SAME_WORDS` or by adding agent-written gold.

3. **One real scoring defect, found on the way.** A candidate relation already consumed by an exact
   match stayed eligible for the `modal`/`typed` contradiction buckets, so one candidate edge could
   both preserve one query relation and contradict another over the same node pair — against the
   module's own stated contract that unobserved evidence is not a contradiction. Fixed; sign,
   assertion and direction conflicts deliberately left unfiltered so polarity rejection cannot
   weaken, with a regression test for each half. r0-v0.2 gate values are byte-identical before and
   after, which is the point: gold does not exercise this case.

4. **A product defect found by using the product, not by reading it.** Executing Card B through a
   real Claude custom connector: `resonance_prepare_thought` derived the durable presentation
   `{topic, domain, cluster_id}` only from `thought.topic`/`thought.domain`, while the tool tells
   callers to prefer `context`. On that path there was no way to name the thought, so every raw-text
   share was published as `Shared thought` / `general` / `shared-thought` — the label another person
   reads when deciding whether to ask for an introduction, and the key the rich-results aggregation
   clusters on. That is exactly where the duplicated "Shared thought" rows came from. `topic` and
   `domain` are now optional arguments on both paths; verified live afterwards.

5. **Card A: 16/18, and neither failure was papered over.** Native `document.modelContext` is absent
   in stock Chromium 141, so native WebMCP stays unclaimed. `cards=0` after a LIVE discover was
   traced to `primary_matches()`, which drops every `negative` match by design — against the current
   corpus every live match is `negative`, so the empty rail is *correct* fail-closed behaviour. The
   defects around it (a summary reading "10 matches · 5 rejected" over an empty rail, and an evidence
   panel still showing REPLAY content) are reported as open R9 work. No acceptance assertion was
   relaxed to turn the run green.

## What was deliberately not done

- **No threshold moved.** The only scoring change is the double-count fix, which leaves every
  benchmark gate value identical.
- **Benchmark gold untouched.**
- **`SCORE_MODEL_VERSION` not bumped.** Bumping it to `0.2.1` was tried and reverted: it feeds the
  verifier config hash, which feeds the `match_id`s pinned in the accepted R8 fixture
  `src/discovery/fixtures/example_response.json`. Diffing live against replay showed *only*
  `match_id` differing while classification, scores, confidence, display and evidence stayed equal.
  Regenerating an accepted fixture to accommodate a cosmetic string is not a reason to touch it.
- **Old duplicate rows not deleted.** They are real `volunteer` records created by earlier runs, not
  by this one. Their session ids are listed for the owner; an agent deleting other runs' data would
  be the wrong default.
- **`RESONANCE_DB` and `RESONANCE_CONFIRMATION_SECRET` not read or modified**; `RESONANCE_SEED_DEMO`
  never set.

## Correction to my own record

PR #162's squash message reports "On the production A/A' pair: contradiction 0.071 -> 0.0". Those
figures are from the **synthetic reproduction** written for the regression test; the PR body says so,
the commit message does not. Measured afterwards on the real production rows the pair is
`approximate`, structural 0.776, `r_direct` 0.714, contradiction **0.143**, one contradiction,
confidence low — and that contradiction is genuine, because the candidate asserts a differently-typed
*unconsumed* relation between the mapped pair, precisely the case the fix leaves alone. Corrected in
the evidence summary and in a comment on #162. Nothing in the code, the tests or ADR-0005 changes.
